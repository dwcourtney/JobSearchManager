# Credential context rules and migration audit

The credential catalog remains the authority for named credentials: version 15, 115 entries, 210 aliases, including 99 custom regex patterns. The catalog is untouched. Its repository/LF SHA-256 is `61b13e1e0043c8d73073ee7b9d6d16e5f141d44f70f7542d7e1fca522d1e9a65`; the existing Windows CRLF checkout has SHA-256 `212f94357bc7919443b36162a0cd91bc943de6b580c5f2c5becf7c97f09b6ccb`. Catalog validation normalizes line endings only for the migration test fingerprint; the catalog loader is unchanged. Names, issuers, categories, families, equivalences and related-credential IDs remain in `CredentialCatalog.json`.

The audit found two remaining domain expressions: `GeneralCredentialLanguageRegex` recognizes credential/licensure vocabulary; `IgnoredGeneralLanguageRegex` excludes irrelevant or generic contexts including certificate management, licensed software, identity/credential/access management and OEM technician wording. These exact expressions now live in `rules/credential-v1.json`, version 1.0.0. Neither their alternation order nor regex options changed.

`CredentialRules` validates the packaged file before host startup. Missing/malformed JSON, unknown members, missing/duplicate/unsupported pattern IDs, invalid expressions and non-finite/out-of-range timeouts fail with a credential-specific diagnostic. Startup logs the ruleset version and SHA-256 of the original file bytes. The schema documents the shape; the loader additionally validates unique, complete pattern references. Matching retains IgnoreCase + CultureInvariant and the existing 250 ms timeout; the configured ceiling is also 250 ms. Catalog and generic grammar matchers retain their existing 250 ms limits and timeout exception behavior.

The remaining C# expressions implement HTML segmentation/normalization, requirement section state, required/preferred/desired grammar, alternatives/equivalence, post-hire/in-progress language, and conservative unknown-name extraction. Those mechanics stay in C#: moving them would expand this conditional vocabulary migration into a grammar engine. Grouping, ordering, evidence truncation, output fields and catalog version are unchanged.

The browser `credential-fit.js` contains inventory/relationship evaluation, alternative-group handling, typed status decisions and display text; it contains no named credential recognition vocabulary and is unchanged. Job Fit and At a Glance are unchanged.

`Tests/LegacyCredentialBaseline.cs` freezes the former implementation. `credential-fixtures.json` freezes results before production changes, exercises every catalog entry and covers requirements, alternatives, post-hire cases, unknown credentials and exclusions. Migration tests compare every serialized analysis field and original expression/options/timeout, validate malformed configurations and prove vocabulary/exclusion edits are applied. The parity CLI `--credential-parity INPUT OUTPUT` also accepts copied cached or curated descriptions. `Tests/credential-downstream.tests.cjs ROOT OUTPUT.outputs.json` compares credential assessments/card badges and actual Jobs-caller scores across configured profiles and travel/work-location preferences. No provider refresh is needed.

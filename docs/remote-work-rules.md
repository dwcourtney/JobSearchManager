# Remote-work parsing rules

Production rules live in rules/remote-work-v1.json with schema version 1, ruleset version 1.0.0, and rules/remote-work-v1.schema.json. All 16 original regex patterns, the literal airport exclusion, ordered signal rules, tentative-presence override and travel category/reason mappings are declarative. Regex options remain IgnoreCase, CultureInvariant and Compiled; the original one-second finite timeout is preserved.

C# retains numeric percentage parsing and 0..100 validity bounds, metadata aggregation, plain-text/section mechanics, generic exclusions/conditional application, signal deduplication/ordering/limits, typed categories/results and evidence construction. The airport exclusion deliberately remains an ordinal-ignore-case literal match; converting it to regex could change edge-case behavior. Analysis version stays 3. Current Job Fit, preferredWorkLocation, concept taxonomy/rules, SQLite authority and browser rendering are unchanged.

The default loader validates before host startup. Missing files, malformed JSON, unknown properties/schema/mappings, invalid regexes/references/scopes/capture groups, duplicate IDs/priorities, incomplete overrides and invalid travel bands fail clearly without a fallback. A regex timeout throws with the rules version and fingerprint. Rules identity is public on RemoteWorkDetector and logged at startup. JSON vocabulary can be changed without recompilation, then applied by restarting. Existing rules/**/*.json packaging and LF attributes preserve exact fingerprint bytes on Windows/Linux.

Tests/LegacyRemoteWorkBaseline.cs freezes the old detector from 39287729a69d64bdf39cb45320e7dab6a286245d. Tests/remote-work-fixtures.json contains 67 outputs captured before production changes. The parity tool compares every result field and downstream classifier output using a disposable SQLite rule store initialized from the unchanged production seed (with usage accounting disabled). No production database is modified. Cached corpus inputs include actual title, primary location and additional-location metadata; curated description-only inputs default to remote designation to exercise obligation detection.

Run the full .NET suite normally. For external JSON records {id, html, title, primaryLocation, additionalLocations}, run Tests/bin/Release/net10.0/JobSearchManager.Tests.dll with --remote-work-parity input.json report.json. It also emits report.json.concepts.json for node Tests/remote-work-downstream.tests.cjs <repository-root> <concepts-file>, which compares full Job Fit results through the actual Jobs caller across work-location/travel preference combinations and exercises remote/onsite/hybrid/null/disabled/TBD cases. Test-only baselines, fixtures and external parity inputs are excluded from production publish.

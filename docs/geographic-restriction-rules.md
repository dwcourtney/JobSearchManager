# Geographic-restriction rules

`JobAnalysis.AnalyzeRemoteLocation` remains separate from `RemoteWorkDetector`. Version 1.0.0 in `rules/geographic-restriction-v1.json` owns six exact expressions, the original literal spellings (`Remote` for primary/additional metadata; `remote` for description), five category mappings and explicit priorities. C# retains ordinal-ignore-case literal matching, generic matching/precedence, existing sentence normalization and snippet construction, typed results and provider inputs.

Rules run in ascending unique priority, then sentences in original order. The first non-excluded match wins. The commuting-plus exclusion is attached declaratively to the commuting-distance rule. U.S. negative lookaheads, substring remote detection, category order and evidence indexing are preserved, including existing surprising cases. There is no remote-work parser merge, scoring change or provider change.

All six recognition/exclusion matchers now have a finite 1,000 ms timeout per regex operation (configurable 1–1,000 ms). Their text and IgnoreCase/CultureInvariant options are unchanged. A timeout throws a diagnostic with ruleset version/hash and the underlying RegexMatchTimeoutException; no fallback pattern or default result masks it. This is a per-match bound, not an end-to-end analysis deadline. Shared HTML/whitespace/sentence/snippet helpers are unchanged to avoid affecting salary, clearance and other callers.

Missing/malformed rules, schema/type violations, invalid expressions, duplicate pattern/rule IDs, duplicate/out-of-range priorities, unknown categories and unresolved references fail before listening. JSON schema documents the shape; the loader additionally validates unique identities/priorities and cross-references. Original bytes are SHA-256 fingerprinted and startup logs version/hash. Packaging uses the existing rules directory inclusion and LF attributes.

The result has exactly IsRestricted, Category and Snippet. It has no independent analysis-version field. Provider analysis version remains 7 and is asserted by parity tests; no cache schema/version migration is introduced. Changed precedence outcomes are reported as changed winning category or snippet, with frozen multi-category and repeated-sentence cases additionally preserving first-category/first-sentence behavior.

`Tests/LegacyGeographicRestrictionBaseline.cs` freezes the original implementation. The 79 fixture outputs were produced before production changes; curated and copied-cache corpora run through `--geographic-restriction-parity INPUT OUTPUT`. Tests compare all result fields and provider version, reflect the original six expressions/options/infinite timeout, prove JSON cue/order/exclusion changes take effect and exercise a pathological regex through the real parser. `Tests/geographic-restriction-downstream.tests.cjs ROOT OUTPUT.outputs.json` executes actual served card/At a Glance statements and the actual Jobs caller to compare old/new and list/detail results.
